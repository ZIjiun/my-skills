# 用 Gemini 讀總覽圖（省 token 的做法）

總覽圖（`frames_scan/sheet_XX.jpg`）每張都是大圖，放進對話後之後每一步都會被重讀，是用量最大的來源。
這份做法請 Antigravity CLI（`agy`）裡的 Gemini 先把總覽圖讀成文字索引，Claude 讀索引、不再自己看總覽圖。

## 原則：Gemini 只「找位置」，Claude 負責「確認」

- Gemini 的索引只用來知道「哪個時間附近有什麼畫面」。
- 寫進筆記的每個字、數字、表格、小字，都由 Claude 從**原解析度截圖**或字幕確認，不直接採用索引裡的內容。
- 索引裡標「看不清」的地方，一定回原圖確認。
- 分段整理、寫筆記、對照字幕的審查、寫進 Notion 都留在 Claude。

## 什麼時候用

三個條件都成立才用，缺一個就照 SKILL.md 第 4 步，由 Claude 自己看總覽圖：

1. `agy` 可以用（`agy --version` 有回應）。只有在使用者自己的電腦上才可能成立；雲端環境叫不到。
2. 使用者同意把畫面傳給 Google（開始前問過）。總覽圖裡可能有帳號、密碼、會員資料、瀏覽器分頁。
3. 影片的總覽圖多到值得（超過約 15 張；很短的影片直接自己看比較快）。

## 步驟

1. 照常跑 `scan_frames.py`，得到 `frames_scan/`。
2. 產生索引（固定用 Gemini 4 Neon，4 張同時跑，每張約 40–55 秒；中斷後重跑會續做）：
   ```
   python scripts/index_sheets.py frames_scan
   ```
   - 結束碼 3：沒有 `agy`，改由 Claude 自己看總覽圖。
   - 結束碼 2：有幾張失敗，印出清單；重跑一次，仍失敗的那幾張由 Claude 自己看。
   - 一律用 `--model` 指定 Gemini。不指定時 `agy` 用介面上選的模型，可能是 Claude，那就沒有省到。
3. 用腳本核對索引有沒有漏格（不靠 AI）：
   ```
   python scripts/check_index.py frames_scan
   ```
   結束碼 1 表示有幾格沒出現在索引裡，清單在 `frames_scan/index_missing.txt`。Claude 打開那些時間所在的總覽圖補看。
4. Claude 讀 `frames_scan/sheet_index.md`（以及 `segments.txt`、精簡字幕），決定要哪些畫面。不用再看全部總覽圖。
   - 索引提到某張投影片、但字幕沒講到：它是「只出現在畫面上」的內容，一樣要處理。
   - 字幕提到「這張圖」「這個表」、索引卻找不到對應畫面：打開那一段的總覽圖自己看。
5. 選定的時間點回原影片抽**原解析度**畫面（SKILL.md 第 4 步「第二段：出圖」）。
6. **逐張看原圖、把文字抄下來**：有 subagent 時，派一個小幫手打開選定的原解析度截圖，把圖上的標題、數字、表格、小字抄成文字交回主流程（附檔名和時間）。主流程之後只讀這份文字，不把圖片留在對話裡。沒有 subagent 時主流程自己看，看完把文字記下來。
   - 圖上的數字以原圖為準；小幫手看不清的，標「看不清」，再裁切放大重看。

## 審查時

- 第 1 輪審查者讀 `sheet_index.md`、`segments.txt`、字幕和初稿，不看總覽圖；索引提到、字幕沒提到、筆記也沒寫的畫面，要打開原圖看過才回報。
- 另外可以請 Gemini 當第二雙眼，對照索引和初稿，只回報可疑漏掉的畫面（它不改筆記）：
  ```
  agy -p "讀 sheet_index.md（畫面索引）和 筆記.md（筆記初稿）。列出：畫面上有教學內容（投影片、圖表、網站畫面的重點）、但筆記完全沒提到的地方，每項寫時間和一句話說明。只回報，不要修改任何檔案。看不清的不要猜。" --model gemini-4-neon-medium
  ```
  Claude 逐項打開原圖確認，確實有內容才補。

## 已知限制

- Gemini 讀大字準，小字和表格數字會讀不清（它會標「看不清」；但不指示「不要猜」時會亂編，所以提示已經寫死）。不要用 Gemini 4 Argon：測試時叫它不要猜仍大量編造。
- 索引沒提到的畫面，Claude 就不知道。`check_index.py` 只能保證每一格都被列到，不保證每格都描述得完整，所以第 1 輪審查仍要對照字幕和 `segments.txt`。
- 畫面內容會經過 Google。
